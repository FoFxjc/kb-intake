# Stage U: React UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v2 static UI with a React 18 + Vite + TypeScript app that implements the approved prototype on the frozen API, ships prebuilt inside the Python package, and works offline.

**Architecture:** Source in `web/`; `npm run build` writes `src/kb_intake/service/static/` (committed; served at `/ui/` by the existing `StaticFiles` mount). API types are generated from `contract/api/openapi-v1.json`. PDF pages render with pdfjs-dist from `GET /v1/jobs/{id}/source.pdf` (HTTP Range); boxes (PDF points, top-left origin) are drawn as an absolutely positioned overlay scaled to the rendered page.

**Tech Stack (exact versions):** react 18.3.1, react-dom 18.3.1, pdfjs-dist 6.4.299, @tanstack/react-virtual 3.14.21, @fontsource/ibm-plex-sans 5.3.0, @fontsource/ibm-plex-mono 5.3.0; dev: vite 8.3.5, @vitejs/plugin-react 6.1.2, typescript 7.0.2, @types/react 18.3.31, @types/react-dom 18.3.7, openapi-typescript 7.13.0, @playwright/test 1.64.1. Node 26 (`web/.nvmrc`).

**Spec:** `docs/intake-ui-llm-design-v1.md` §5 (authoritative); the prototype `docs/ui-prototype/*.dc.html` (layout, wording, colours, states — read all four); `docs/api-v1.md` (the API). Decisions: per-job describe / chart_table switches go in the workflow YAML `llm` block; "Description is wrong" / "Hint is wrong" are `ack` with `verdict: "wrong"`; queue items shown are reported with `POST /queue/seen`.

## Global Constraints

- All UI text in English; no CJK characters in `web/` or `static/` (CI checks).
- No network access other than the same origin: fonts, pdf.js worker, cmaps and standard fonts are bundled; no CDN URL anywhere in the built files.
- Only the frozen API (`contract/api/openapi-v1.json`) is called; no endpoint or field outside it. The generated types (`web/src/api/schema.gen.ts`) are the only API types.
- Reads `GET /v1/health` → `llm.enabled`; when false, every LLM element is hidden (summary card, LLM toggles, `describe` handler option, LLM description panels, `llm_check` group label stays only if items exist).
- Exactly the pinned dependency versions above, `package-lock.json` committed; no other runtime dependency.
- The build is reproducible: `npm ci && npm run build` on Node 26 gives byte-identical `static/` (CI rebuilds and diffs).
- Colours, spacing and type follow the prototype (IBM Plex Sans / Mono; the colour values in the prototype's inline styles become CSS custom properties in `web/src/styles/tokens.css`).
- Python side: `src/kb_intake/service/app.py` keeps serving `/ui/`; the old `static/app.js`, `index.html`, `style.css` are replaced by the build output. Tests in `tests/test_service.py` that assert the old files are updated to the new entry (`/ui/` returns the built `index.html`; no `http(s)://` URL in any built HTML/CSS/JS except inside the bundled pdf.js licence comments, checked by a dedicated test that lists the allowed exceptions).

## Review Focus

1. A 276-page PDF: the page viewer must only render the visible page (and the thumbnail strip lazily), never all pages; switching pages fast must not leave stale canvases or leak workers. → Task 3 Playwright `page switching renders one canvas`.
2. Search typing: requests are debounced (200 ms) and an older response arriving after a newer one must not overwrite the list. → Task 4 unit test on the request sequencer.
3. Bulk actions on a cluster of 185 regions: one `POST /review` with all ops; members already excluded or absorbed are left out client-side; a 400 shows the server's message and changes nothing. → Task 6 Playwright.
4. The job is busy (409) or in the wrong state: the UI shows the server message and a retry, never a blank page. → Task 2 component test + Playwright on approve twice.
5. LLM disabled: no LLM element is rendered and no `/summary` or `/llm` polling happens. → Task 5 Playwright with `llm.enabled = false`.

## Tasks

### Task 1: Scaffold, build, CI (main session reviews the lockfile)
- `web/` with the pinned versions; `vite.config.ts`: `base: '/ui/'`, `build.outDir: '../src/kb_intake/service/static'`, `emptyOutDir: true`, `sourcemap: false`, fixed `assetFileNames` pattern with content hashes; `npm run build` = gen-api → `tsc --noEmit` → `vite build` → copy pdf.js assets.
- CI job `web`: `actions/setup-node` with `node-version-file: web/.nvmrc`, `npm ci`, `npm run build`, then `git status --porcelain src/kb_intake/service/static web/src/api` must be empty.
- Python tests updated for the new static entry; `uv tool install` packaging check (wheel contains `kb_intake/service/static/index.html` and the pdf.js worker).
- `tests/e2e_server.py` (Python, test-only): `uv run python tests/e2e_server.py --port 8799 [--llm-url URL]` serves `create_app` on a temp work dir with the fake Docling engines of `tests/jobflow.py` (two pages, a table, a p106-like suspected table, a bar chart) and, with `--llm-url`, the LLM enabled against `tests/fake_llm.py`. Every Playwright spec except `ocbc.spec.ts` runs against it, in CI too (job `web` installs Chromium with `npx playwright install --with-deps chromium`).
- Done when: `npm run build` twice gives identical files (sha256 of every file), CI job green, `uv run pytest -q` green.

### Task 2: App shell, API client, jobs and upload
- Header (file name, pages, language, job id), StepBar per prototype (states done / now / run / todo derived from job status), ErrorBanner for ApiError (status + detail), Busy indicator (polls `GET /v1/jobs/{id}` every 2 s only while `running_op` is set).
- Jobs page: list (`GET /v1/jobs`), upload form (file + declaration fields → YAML text: doc_id, issuer_id, doc_type, period_end, source_url, completeness.full, lang), existing-job notice from `existing_job` / `existing_note`.
- Done when: `web/e2e/shell.spec.ts` passes against the fake-engine server (Task 1): upload creates a job and lands on Labels; uploading the same file shows the existing-job notice; a 409 shows the ErrorBanner.

### Task 3: PDF page and overlay
- `PdfPage`: loads the document once per job (`pdfjs.getDocument({url, rangeChunkSize: 65536, disableAutoFetch: true, cMapUrl, standardFontDataUrl})`), renders one page to a canvas at device-pixel ratio, cancels the previous render task on page change.
- `Overlay`: boxes in PDF points → percentage of page width/height; region boxes coloured by type (prototype colours), selected box thicker; cell boxes and find_tables boxes dashed as in the Review prototype; search match box highlighted.
- Done when: Playwright on OCBC p106 shows the table_suspected box and the find_tables cell grid; switching pages 20 times leaves one canvas.

### Task 4: Labels & inventory page
- Metadata card (`GET /v1/jobs/{id}` stats), Document summary card (`GET /summary`; hidden when LLM disabled; purple "Generated by <model> · low weight · for reference" chip and the remote notice when `remote`).
- Left: Region types (facets `type`, grouped as in the prototype: Tables, Charts, Diagrams, Pictures, Icons, Logos, Signatures, Text = all textual types), Needs attention (facets `gap`).
- Middle: virtualised region list (`GET /regions`, cursor paging on scroll), search box (debounced, latest-wins), row = page, type chip, text preview with the match snippet (« » rendered as `<mark>`), flag, score.
- Right: page view of the selected row with overlay; details (type, confidence, region id, flag, text).
- Done when: Playwright: search "overdue" lists p106 first page hits; type filter Tables shows only tables; facet counts change with the query.

### Task 5: Workflow & approval, progress
- Handler table per type with the options of the prototype; `describe` only for chart/diagram/picture and only when `llm.enabled`; Excluded pages input (`1-4, 270-276` syntax → list).
- LLM panel (only when enabled): the remote notice with the configured host, three switches — summary shown read-only (config), describe and chart_table write the workflow `llm` block.
- "This run will process" summary computed from facets and the current handlers; Approve (`PUT /workflow` with the YAML, then `POST /approve` with `by`).
- Progress page: events (`GET /events?after=` every 1 s while running): Docling step, regions, LLM descriptions done / total (from the `llm` events), then a link to Review.
- Done when: Playwright approves OCBC with charts on describe (LLM enabled run) and with LLM disabled (no LLM element in the DOM, no `/llm` request).

### Task 6: Review inbox
- Left: queue groups (`GET /queue`) with done / total and progress bar; Similar groups (`GET /clusters`) with bulk action: "Exclude all" (one `POST /review` with an exclude op per member not excluded / absorbed) or "Open this group" (filters the list to the members).
- Middle: the current item's page with overlay (region box, cells, find_tables box), prev / next (keyboard ← →), "item n of N"; each shown item is reported with `POST /queue/seen` (batched, at most once per item).
- Right: issue title and detail; LLM description panel (purple, low weight) for `llm_check` items and regions with `llm`; chart table (from `/llm?region_id=`) when present; actions by item kind: reclassify (type select), exclude, ack ok / ack wrong (with optional note); resolved state per the prototype.
- Done when: Playwright on OCBC: p106 reclassify to table (29 regions absorbed shown), bulk exclude of an icon group (review rows per member), ack one item, counts update.

### Task 7: Confirm & deliver; end-to-end
- Deliver page per prototype: KPIs (regions, tables, LLM outputs, open issues, contract check after delivery), open vs resolved per gap code (`GET /gaps`), human actions (`GET /review`), package file list (from the prototype's list; `llm.jsonl` only when used), Confirm (`POST /confirm`), delivered state with the package name and check (`GET /v1/packages`).
- `web/e2e/ocbc.spec.ts` (run locally, not in CI: needs the models): upload OCBC (or open the existing job), search, filter by type, approve (with describe when the LLM is enabled), wait for extraction, review inbox (p106 reclassify, bulk exclude icons, ack one), confirm; a screenshot per page into `web/e2e/shots/`; asserts zero console errors and zero requests to any host other than the server.
- Done when: the spec passes twice on OCBC (LLM disabled; LLM enabled with the key), screenshots committed to the PR description (not the repo).
