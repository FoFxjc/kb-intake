# kb-intake demo v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the one-shot `scan` into the step-wise scan layer of intake-design-v2: label -> plan -> approve -> extract -> review -> confirm -> deliver, with two human gates and contract v2 packages.

**Architecture:** One SQLite job store (`kb_intake.jobs`, done) shared by the CLI and `serve`. Each step is a module with a `run(...)` that moves the job through its states. Docling only gives structure (regions, table grids); every text is read from the PDF text layer by box (`kb_intake.textlayer`, done). The work directory holds each job's intermediate files; only `deliver` writes the delivery folder, atomically.

**Tech Stack:** Python 3.12, Docling 2.140.0 (pinned), PyMuPDF 1.28.2, FastAPI + static HTML, SQLite, pytest.

**Spec:** `docs/intake-design-v2.md` (authoritative; read in full), `docs/intake-design-v1.md` §2 and §9.3 (stability rules), `docs/layout-design-v1.md` §2 (region types).

## Global Constraints

- Everything in this repository is English: code, comments, docstrings, UI text, tests, commit messages. No CJK characters in `src tests scripts contract` (CI greps for them; write CJK only as `\uXXXX` escapes via a Python script, never through an editor tool).
- Text comes only from the text layer: `textlayer.words(page)` / `textlayer.words_in` / `textlayer.text_of`. Never use Docling's text.
- Coordinates: TOPLEFT origin, PDF points, full precision (no rounding).
- Determinism: the same source + workflow + review ops give byte-identical packages except `manifest.run`, `review.jsonl` `at`, `workflow.json` `approved_at`, `manifest.workflow.approved_at`, `manifest.status.confirmed_at` (and the `files` hashes of the two files that hold those times). Serialise with `kb_intake.package` helpers; never iterate over sets or dicts whose order depends on input timing.
- Region types, handlers, statuses, gap codes: only the names in `kb_intake.vocab`. Gap rows must validate against `contract/v2/gap.schema.json` (fields: `code`, `page_no`, `detail` required; optional `region_id`, `table_id`, `source`, `side`, `bbox`, `pages`, `extractor`, `count`).
- No network at run time; Docling runs only through `kb_intake.runner.run` (child process, hard timeout, cache).
- Do not modify the foundation modules (`jobs.py`, `vocab.py`, `config.py`, `engines/*`, `runner.py`, `textlayer.py`, `geometry.py`, `package.py`, `contract.py`, `contract/v2/*`). If one needs a change, say so in your report instead.
- Low-confidence threshold: `cfg.low_confidence` (default 0.5). Table matching threshold IoU >= 0.5 (`geometry.match_one_to_one`).

## Review Focus

1. A page with no text layer (scanned page in a native PDF): text handler yields `text: null`, a `no_text_layer` gap per page from label; nothing crashes.
2. Docling fails or times out in either stage: the job continues with `extractor_degraded` (label: native-text regions + find_tables tables; extract: find_tables in each table region's box).
3. Reclassify the same region twice, or reclassify an excluded region: the second is refused before anything is applied (ops are all-or-nothing per call).
4. Delivery when the package directory already exists in the delivery folder, or a stale `.tmp-*` from a crash: refuse / clean up, never a partial package under the final name.
5. Two processes (CLI and server) touching one job: `jobs.running` compare-and-set makes the second one Busy, not a double run.

## Work directory (shared interface)

```
work_dir/jobs/<job_id>/
  source.pdf
  label/   pages.jsonl  layout.jsonl  regions.jsonl  gaps.jsonl  stats.json  docling.json  run.json
  extract/ regions.jsonl  tables.jsonl  gaps.jsonl  docling.extract.json  run.json
  review/  gaps.jsonl
```

- `label/pages.jsonl`: `textlayer.page_record` rows (no `excluded`). `label/layout.jsonl`: `textlayer.layout_record` rows.
- `label/regions.jsonl` (label-stage region): `region_id, page_no, bbox, type, subtype, score, label_source, layer, reading_order, font` plus work-only `docling_label` (str or null) and `classes` (classifier ranking or null).
- `label/run.json`: `{"seconds", "engine": {"status","seconds","cached","cache_key","failed_pages","errors","dropped_table_cells","unscored"}, "engines": {"docling": <version>, "models": models.pins(), "params": {"label": ...}, "pymupdf": ..., "device": ...}, "detection": <detect summary>, "declaration_filled": [...]}`
- `label/stats.json`: `{"pages", "pages_by_kind", "regions", "regions_by_type", "low_confidence", "table_suspected", "estimated_extract_seconds", "label_seconds", "workflow_notes": [...]}`
- `extract/regions.jsonl`: contract v2 region rows (schema `region`), all regions, reading order. `extract/tables.jsonl`: contract v2 table rows. `extract/gaps.jsonl`: extract-stage gaps. `extract/run.json`: `{"seconds", "engine": {...as label}, "params": {"extract": ...}, "unmatched_extract_tables": n}`.
- `review/gaps.jsonl`: gaps produced by review re-extraction (e.g. find_tables found nothing).
- A region's extract-stage gaps (`region_id` set) live in `extract/gaps.jsonl` until review re-extracts that region; then they are removed there and the new ones written to `review/gaps.jsonl`.

Delivery gaps = label + extract + review gaps, sorted by `(page_no or 0, code, region_id or "", table_id or "", detail)`.
